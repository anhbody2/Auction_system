# sec-003 short access token plus a stored, rotating refresh token

SRS: System - Security Functional ("clear refreshToken"; prerequisite for sec-005). Design: docs/session-tokens.md.

| File | Change |
|---|---|
| be/prisma/schema.prisma, migrations/20261022100000_refresh_tokens | New table `refresh_tokens` (hash only; revoked, never deleted). |
| be/src/config.ts | `refreshCookieName`, `accessTokenTtlMs`, `refreshTokenTtlMs`, `idleTimeoutMs`, `refreshReuseGraceMs` (env overridable). |
| be/src/middleware/auth.ts | `signToken` expiry = access TTL (was 7 days). |
| be/src/lib/session.ts | New: `startSession`, `rotateSession` (rotation, reuse detection, grace window, idle limit), `endSession`, `revokeAllSessions`, `clearSessionCookies`. |
| be/src/routes/auth.ts | Login and activation sign-in use `startSession`; new `POST /refresh`; logout revokes (reason `logout`/`idle`) and clears both cookies; reset-password revokes all. |
| be/src/routes/me.ts | Password change revokes all sessions, then starts a new one for this browser. |
| be/src/routes/adminUsers.ts | Lock, soft delete and set-password revoke all of the user's sessions. |
| fe/src/api.ts | `refreshSession()` (shared in-flight request); 401 -> refresh once -> retry once; sign-out only if the refresh fails. |
| fe/src/store/authedStream.ts | New: reopens an SSE stream after a 401 reconnect once the session is renewed. |
| fe/src/store/useUserEvents.ts | Uses `openAuthedStream`. |
| be/tests/helpers.ts | `refresh_tokens` in the reset; `setCookie`, `loginTokens`, `refreshWith` helpers. |
| be/tests/auth.refresh.test.ts, auth.logout.test.ts, auth.revoke.test.ts | New. |
| fe/src/api.test.ts | New refresh/retry cases; the existing 401 cases kept (they now also go through a failed refresh). |
| fe/src/store/authedStream.test.ts, e2e/sec-003-refresh-token.spec.ts | New. |
| docs/session-tokens.md, docs/ERD_edited.md | New topic doc; ERD row and table. |
