# stf-006 staff auction management

SRS: Staff - Auction Management, REQ-1, REQ-2. Delete rules: docs/auction-cancel.md "Staff delete".

API: `/api/staff/manage/auctions` (permission `auction.manage`, staff and admin). `/api/staff/auctions` was already
the stf-001 statistics list, so the management routes got their own prefix. UI: /staff/auctions, nav "Manage auctions".

| Route | Notes |
|---|---|
| `GET /` | `q` (name), `seller` (username or full name), `status` (all, upcoming, active, ended, cancelled, deleted; derived from times like the public pages), `from`/`to` start-date range (local days, `tz`), paging. Combined with AND. |
| `GET /seller-goods?seller=` | The seller's approved goods available for a new auction (form picker). |
| `GET /:id` | Auction (with reserve, settlement, deletedAt) and all bids. |
| `POST /` | `seller` + the seller create-auction body. Goods must be the seller's, approved and available, otherwise 400 with the reason on `goodsId`. Stored `upcoming` (sell-007 'New'). |
| `PATCH /:id` | Upcoming: name, description, prices, start time, duration (end recomputed). Started: description only (400 otherwise). Cancelled/deleted: refused. |
| `DELETE /:id` | Soft delete, see docs/auction-cancel.md. |
