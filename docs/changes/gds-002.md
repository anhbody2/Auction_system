# gds-002 - Edit and delete goods, blocked while in an auction or sold

SRS: Seller - Manage Goods 3.11.3 REQ-2.

## Behaviour

- My goods has an Actions column. Available goods: **Edit** (opens `/goods/:id/edit`, the same form as
  Add goods, filled in) and **Delete** (inline "Delete <name>?" with Yes, delete / Keep).
- Goods in an upcoming or active auction, or sold: Edit and Delete are disabled and the reason is shown
  ("Goods in an active auction cannot be changed" / "Sold goods cannot be changed").
- Goods whose only auction was cancelled, or ended without a winner, count as available again.
- Delete is a soft delete (`goods.status = 'deleted'`) because `auctions.goods_id` references the row;
  deleted goods drop out of My goods and every goods endpoint, while past auctions still load them.

## API

| Endpoint | Notes |
|---|---|
| `GET /api/goods/:id` | owner only; adds `lockedReason`. 404 for someone else's, deleted or unknown goods. |
| `PATCH /api/goods/:id` | owner only. Any of name, description, categoryId, condition, images (strict; same rules as create). Sent images replace the current list. 409 when in an auction or sold. |
| `DELETE /api/goods/:id` | owner only. 200 "Goods deleted"; 409 like PATCH. |

The check and the change run in one transaction that first locks the goods row (`SELECT ... FOR UPDATE`,
`lockOwnGoods` / `lockChangeableGoods` in be/src/lib/goods.ts), so an auction cannot be created for the goods
between the check and the change once sell-003 takes the same lock.

Non-owners get 404 rather than 403 so goods ids of other sellers are not confirmed.
